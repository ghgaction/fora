Annotation Reference

  1. 1
    Per-project scope — the org switcher selects one project; everything authored here is scoped to it. Structured records (profile, assurance, rating, credits, claim-boundary) and free-form streams (journals, documents, SDG) share one index.
  2. 2
    Section index with state — each content type shows Draft / In gate / Published, so an author sees the whole authoring surface and what still needs attention at a glance.
  3. 3
    Authored-only boundary — measured data (carbon, hydrology, species) is piped from PBPH-RE and is deliberately absent from this index; Fora authors documents, status, numbers, and stories.
  4. 4
    Editor — shown with the Journal type (most editorial); structured types reuse the same frame with fielded inputs instead of rich text. Buyer-facing placement decides where published content lands in the buyer app.
  5. 5
    Gate seam — Submit to Disclosure Gate creates a Pending row in that screen; content never goes live from here. “Request changes” in the gate returns the draft to this editor.
  6. 6
    Completeness meter — authored-and-published count feeds the buyer-facing disclosure-completeness meter (filled vs pending), the project’s honesty signal.
